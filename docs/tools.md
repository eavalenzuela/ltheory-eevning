# Developer tools

Everything here runs from the repository root after `python3 configure.py build`.

## Is the tree healthy?

| Command | What it does |
|---|---|
| `script/check` | Type check, engine-free specs, and the launcher's exit codes, each paired with a planted failure that must be caught. Exits 0 only if every step did what it should. |
| `script/check --fast` | The same without the steps that open a window. |
| `script/check --soak` | Adds the soaks: eight seeds of the 400-system strategic sim, each run in memory and again with a save and load every 97 ticks, for four and a half game days; the economy sweep (16 seeds); the faction sweep (32 seeds). About 25 minutes. |

`bin/launch APP` exits 0 only when the app started, no script raised an error and every harness command worked. A crash or failed assertion exits with 128 + the signal number.

## Engine-free code

`bin/ltcore MODULE [ARG ...]` runs a Luau module with no window, no GL and no engine. Only the built-ins and `Host` (files, directories, clock, arguments, exit) exist there. Code under `resource/script/Core` and `Tool` must run in it; the type checker enforces that. The rules for such code are in `docs/design/core.md`.

| Command | What it does |
|---|---|
| `bin/ltcore Tool/specs [FILTER]` | Runs every `*.spec.luau` under `Core` and `Tool`. |
| `bin/ltcore Tool/econrun [--galaxy N] [--days N] [--out DIR] [--detail 1]` | Runs the galaxy's economy (400 systems, 30 game days by default) and prints a verdict on each of `Tool/EconProbe`'s measures. `--detail 1` adds every class's price level, every step's use and how people fare by security. `--goods 1` and `--atlas 1` print the goods table and who has what. Options such as `--haul`, `--jump`, `--slack`, `--source` override the atlas's settings for one run. |
| `script/econsweep [--seeds N] [--days N]` | `econrun` on 16 seeds at once, with a scorecard of every measure by seed. The exit test of roadmap stage S2; part of `script/check --soak`. |
| `bin/ltcore Tool/factionrun [--galaxy N] [--history N] [--days N] [--out DIR]` | Runs the strategic simulation (the powers, their wars and the pirates on the galaxy's economy; 400 systems, 30 game days by default) and prints a verdict on each of `Tool/FactionProbe`'s measures. `--news 1` prints wars, peaces and the like as they happen (`--news 2`: sieges, claims and raids too); `--every H` prints a line on the galaxy every H hours; `--detail 1` adds a table of the powers, their relations, where every credit came from and went, and the counters. `--out DIR` writes the hourly series, the news and the verdicts. |
| `script/factionsweep [--seeds N] [--days N]` | `factionrun` on 32 seeds at once, with a scorecard. The exit test of roadmap stage S3; part of `script/check --soak`. |
| `script/sweep TOOL NAME ...` | What the two sweeps are made of: runs a tool over seeds in parallel into `cache/NAME/sweep-<time>/` and prints one row per check, one column per seed. `--rescore DIR` prints the scorecard of an earlier sweep. Exits 1 if any check failed. |
| `bin/ltcore Tool/simdiverge [--galaxy N] [--history N] [--ticks N]` | Runs the strategic simulation twice, once with a save and load every 97 ticks, and finds the first tick and the first fields where the two differ. |

To change how the powers behave, edit `resource/script/Core/Data/Powers.luau` (every number of the faction layer, each with what it does), run `factionrun --detail 1 --news 1` on a seed or two to see the effect, then the sweep. A sweep measure that misses is a reason to look at a seed with `--detail`, not to move the limit.

## The game

`bin/launch game` runs the game: the Core shown by the engine (`resource/script/App/game.luau`, `resource/script/Game/`). Left-drag turns the camera and the wheel zooms; click a bracket or an overview row to select, then use the orders on the selected-item panel. It opens on a menu (continue, new game from a seed, load, quit); Escape brings up the menu in play (resume, save, load, main menu, quit). P pauses, F9 saves to `save/quick/`, F10 loads it, and docking saves to `save/auto/`.

`GameDebug` is a global table for the console and for scripted runs: `Order(kind, what, range)`, `Select(what)`, `Docked()`, `InSpace()`, `InWarp()`, `Idle()`, `System()`, `Distance(what)`, `TargetGap()`, `Doing()`, `TimeScale(n)`, `Zoom(radii, yaw, pitch)`, `Save(slot)`, `Load(slot)`, `Hash()`, `Mark(name)` and `Same(a, b)`, `Jumps(n)` and `JumpsLeft()`, `Memory()`, `Vram()`. `what` is a kind (`"belt"`, `"station"`, `"gate"`, `"asteroid"`, `"planet"`) or part of a name, and means the nearest match.

```sh
bin/launch game --console                    # then type: GameDebug.Order("Undock")
bin/launch game --no-present --fixed-step 60 --script test/scenario/flight.txt
```

`test/scenario/flight.txt` (the M1 flight loop), `test/scenario/combat.txt` (the M2 loop: fit, fight, loot, lose the ship, get home) and `test/scenario/economy.txt` (the M3 loop: mine, refine, build, sell by order, buy a hull, train, board) are harness scripts; `script/check` runs all three, `test/scenario/arms.txt` (a Vessari cruiser carries its fitted weapons on its hardpoints, they all fire, and its turret comes round to its target), `test/scenario/starbase.txt` (buy a control tower, fuel and a refining array, anchor the tower at a moon, moor at it, fuel it, anchor the array and refine ore there), `test/scenario/colony.txt` (buy a command centre, put it down on a planet, raise an extractor and a processor, run a programme and take what is made up into the hold), `test/scenario/lawless.txt` (out through low security into lawless space in a Courier: the packs that come, in hulls of the pirates' own, and away again), `test/scenario/menu.txt` (the opening menu, a new game from a seed, a save from the menu in play, loading it, the assets window, deleting the save), `test/scenario/galaxy.txt` (a galaxy of forty systems, the star map, and the autopilot flying the safest way to a far system), `test/scenario/traffic.txt` (haulers and patrols about a homeworld's system, nobody's enemy until a pilot fires on one and is marked), `test/scenario/missions.txt` (the three jobs a station offers: taken, one filled from the market and paid, its loyalty points spent in the faction's store with `LoyaltyStore` and `Redeem:<type>`, one given up; `GameDebug.Loyalty(n)` gives, or sets, the points with the faction docked at), `test/scenario/sites.txt` (two hidden belts found with the ship's scanner, a warp to one, and a scan probe put out with `Probe:launch` and called in with `Probe:recall`; `GameDebug.Probes()` gives how many are out here and in the hold), `test/scenario/tackle.txt` (a webifier and a warp disruptor fitted and used on a pirate), `test/scenario/salvage.txt` (a salvager fitted and a wreck stripped, then looted), `test/scenario/rigs.txt` (a rig built of salvage, fitted, and destroyed by taking it out; a rig's cross on the wheel is `Unfit:rig<n>`), `test/scenario/drones.txt` (drones put in the drone bay with `ToBay:<type>` (and out of it with `FromBay:<type>`), one launched at a belt, fighting the pirate that comes, and called back; the buttons are `Drones:launch`, `Drones:engage` and `Drones:recall`, and `GameDebug.Drones()` gives how many are out, in the bay, and could be out), `test/scenario/fleet.txt` (a pilot hired on the Crew tab and given a second ship, out to a belt with the player, pointed at the pirate that comes, and after the player through a gate and into a station; the buttons are `Hire:<n>`, `Give:<pilot>:<ship>`, `TakeOff:<n>`, `Dismiss:<n>`, `Fleet:engage`, `Fleet:follow` and `Fleet:stay`; `GameDebug.Spare(hull)` puts an armed second ship in the hangar, and `GameDebug.Fleet()` gives how many pilots are hired, are on the player's grid, have a docked ship, and are pointed at something), `test/scenario/miner.txt` (a hired pilot in a mining frigate set to mine a belt with `Fleet:mine`, who brings a hold of ore in while the player sits docked; `GameDebug.Spare(hull, 'miner.small')` gives the frigate its lasers, and `GameDebug.Crew(n)` says what the nth pilot is doing and how much ore they have brought in), `test/scenario/assault.txt` (an assault taken from the home station's fourth agent, its camp warped to, two waves of scouts destroyed there and the job paid; `GameDebug.Offer(kind)` gives the place in the list of the first job of a kind the station offers, for `Accept:<n>`; `GameDebug.Assault()` gives the camp's name, the waves that have come and how many there are, and the ships destroyed and how many there are; and `until GameDebug.Engage() == 0` is a cheat that fights whatever on the grid would fire on the pilot, nearest first, and gives how many are left), `test/scenario/haul.txt` (a hired pilot in a hauler told to sell what they bring in, with `Sells:<n>`, and set to haul ore to another station from the Crew tab: `Haul:what:<n>` goes round the kinds of cargo, `Haul:to:<n>` round the places to carry to, `Haul:go:<n>` gives the order, and `Recall:<n>` calls back one who is out; `GameDebug.Crew(n)` also gives what selling has made and whether the pilot is told to sell), `test/scenario/keys.txt` (a fight flown with nothing in space clicked: `GameDebug.Key('Q')` presses a key by its name, as `Game/UI/Keys` lists them; `GameDebug.Tracking()` gives what the camera is following and where it looks from; it also marks a place and warps back to it, and checks what the guide has ticked off with `GameDebug.Guide(step)`, which gives how many steps are done, of how many, and whether the one named is), `test/scenario/invent.txt` (a tech 2 blueprint tried for on the Industry tab, with the button `Invent`, from a module's blueprint and then from a hull's; a custom make of a gun fitted in place of the plain one; and a tech 2 hull flown, with `GameDebug.Fly(hull)`, its weapons on its mounts), `test/scenario/hack.txt` (a Data Analyzer fitted, a sealed hold's lock begun with `Hack` on the selected wreck, given up with `Hack:abandon`, begun again and won, and the hold looted; a node of the board is `Hack:<n>`, left to right and top row first; `GameDebug.Wreck(true)` leaves a wreck whose hold is sealed, `GameDebug.Hack()` says whether a hack is under way, the coherence left and how many nodes are cleared, and `until GameDebug.HackOn()` plays the hack out, a try a tick at the node nearest the core), `test/scenario/dscan.txt` (the scanner window's directional side, `Scanner:directional` (and `Scanner:signals` back): a scan with `Dscan:scan`, all round or in a cone with `Dscan:angle:<degrees>` (360, 90, 30, 10) pointed at what is selected, at a range set with `Dscan:range:<AU>` (14, 5, 1, 0.1); `GameDebug.Sighted(name)` gives how many things the last scan had whose name has that in it, how many scans have been made, and how many of those things are off the pilot's grid; `GameDebug.Wreck(false, metres)` leaves the wreck that far off), and `test/scenario/pace.txt`, which fails if the game draws under thirty frames a second just outside the home station (a picture cannot show a slow frame: time one whenever something is added to the scene).

In the game, `GameDebug.LookAt('sun')` (or any name the overview knows) swings the camera to look just past the ship at it. `GameDebug.LookFrom('sun', zoom, turn)` puts the camera on that side of the ship instead (its lit side, for the sun), swung round by `turn` radians. `GameDebug.Fly(type)` is a cheat for looking at hulls: while docked, a hull of that type from nowhere, boarded whatever the pilot's skills, with the weapons its design is drawn with (as far as they fit) loaded. `GameDebug.Arms()` says how many weapon models stand on the mounts of the pilot's ship (two to a fitted weapon: a hardpoint is a pair of mounts), and how far from its target the worst-pointed of the turrets that are firing still is.

`script/viewer` runs the viewer: one window that goes through a list of views of a body (in `App/viewer.luau`) and saves a picture of each to `cache/viewer/shots`. It is meant to be started once and left, minimised if wanted, so that no window is opened per picture. `script/viewer start [FILTER]` opens it and takes the views; `script/viewer again [FILTER]` reloads every shader and takes them again (a few seconds); `script/viewer sheet PREFIX` puts the pictures named `PREFIX*` side by side in `cache/viewer/sheet-PREFIX.png`; `script/viewer stop` closes it. With a FILTER only the views with that word in their names are taken (`moon`, `gas`, `star-red`, `rings`, `fx-` for weapons firing, `hull-` for every hull that has a design, from six sides and with its design's weapons on its hardpoints, `arms` for every weapon model and the three sizes side by side, `wreck-` for each hull's wreck, `base-` for the control towers, the station modules and whole stations in their fields, ...). While it waits it sleeps, but close it before timing the game: two programs share the graphics card. `cache/viewer/params.txt` overrides the settings of the kind of body being looked at, one a line: a name and a number (`seaLevel 0.5`), or three for a colour (`rockPale 0.6 0.5 0.4`). Shaders and settings are reloaded on every pass; a change to a script needs `stop` and `start`. A scripted run can hold one view still instead, with nothing read from those files: `bin/launch viewer --do "lua assert(Viewer.Show('gallery')); frames 40; shot golden; quit"`. The golden images `bodies` (every kind of body in one picture) and `effects` (every weapon landing its shot) are taken that way.

A scripted run opens a window that stays black: `--no-present` means frames are drawn and saved but never shown. To watch an app, run it without the harness flags.

A script works the station screens by pressing buttons by name, which runs the same code a click does. A button's name is its label (`UNDOCK`, `Market`, `Skills`) or, where several look alike, an id: `Fit:<type>`, `Unfit:<rack><slot>`, `ToHangar:<type>`, `Refine:<type>`, `Train:<skill>`, `Learn:<skill>`, `Board:<n>`, `Assemble:<type>`, `BuyNow`, `SellNow`, `PlaceSell`, `PlaceBuy`, `StartJob`, `Runs:most`, `Quantity:100`, `Research:material`, `Research:time` (and `GameDebug.Researched(type)` gives the levels learned of a blueprint). The screen is a frame behind the game, so wait for the button rather than asserting it: `until GameDebug.Press('Fit:miner.small')`. `GameDebug.CanPress(name)` and `WhyNot(name)` say whether a button is live; `Enter(field, n)` types into a number field (`Quantity`, `SellPrice`, `BuyPrice`, `Runs`); `Market(type)` and `Blueprint(type)` open the market or industry tab at a row; `Info(type)` opens the information window on a type (as pressing `Info:<type>` does, the name of every item link and Info button; `Info:close` and `Info:back` are its own buttons). At a starbase of the pilot's own the screen has a `Starbase` tab, with `Fuel:hold` and `Fuel:hangar`, `Anchor:<module>` and `Unanchor:<module>`; in space a selected moon has `Anchor tower`; `GameDebug.Tower()` says how the pilot's newest starbase stands (`"none"`, `"anchoring"`, `"dark"` or `"lit"`), its fuel, and how many of its modules are online. The colonies window has `Colonies` (the button that opens it), `Colony` (a selected planet's), `Colony:close`, `Colony:next`, `Colony:deploy`, `Extractor:<raw>`, `Processor:<product>`, `Storage`, `Programme:<facility>:<hours>`, `Remove:<facility>` and `Take:<type>`; `GameDebug.Colony(what)` opens it on a planet, `Deposit(n)` names the nth raw material of the planet shown and its product, and `Colonised(type)` says how many facilities the colony shown has (-1 with no colony), how many are working, and how many of a type its store holds. For the economy there are also `Hangar(type)`, `Skill(id)`, `Training()`, `Jobs()`, `Orders()`, `Ships()`, `HoldFull()`, `Mine()`, `Running()` and the cheat `Grant(credits)`, which is entered in the wallet journal as a cheat. `Order(kind, 'home')` means the pilot's home station. A person starting the game is given a menu and a script is not (`Host.scripted`); `GameDebug.Menu('main')` or `Menu('pause')` opens one as a person would get it, and `Menu()` says which page is up. Its buttons are `Menu:continue`, `Menu:new`, `Menu:load`, `Menu:save`, `Menu:resume`, `Menu:main`, `Menu:quit`, `Menu:back`, `Menu:start`, `Menu:random`, `Load:<slot>`, `Save:<slot>` and `Delete:<slot>`, and the seed field is `Seed`. `GameDebug.Seed()` is the galaxy's seed. A script's saves (`GameDebug.Save`, the menu's) are kept in `cache/test-saves`, a person's in `save/`. `Assets` opens the assets window (`Assets:close`). `Map` opens the star map (`Map:close`, `Map:factions`, `Map:security`, `Map:destination`, `Map:clear`, `Map:safest`, `Map:autopilot`), and `Autopilot` is the switch at the foot of the screen once there is a destination. `GameDebug.NewGame(seed, systems)` begins a game as the menu does; `Galaxy()` gives the number of systems and whose the pilot's is; `Destination(system, safest)` sets where to go (a name or a number) and returns the jumps, and with no argument the jumps left; `Autopilot(on)` switches it; `Far()` names the farthest system that is not lawless, for somewhere to send it. (Two `until GameDebug.Press(...)` lines one after the other can run in the same frame, and the second press replaces the first: wait for what the first press does in between.) The overview's `Scanner` button opens the scanner window (`Scanner:close`, `Scan`, `SiteWarp:<n>` for the nth site listed); `GameDebug.Sites(kind)` gives how many sites the system has, how many are found, and the name of the first found one of a kind; a found site is on the overview as kind `site`. The Missions tab has `Accept:<n>` (the nth job offered), `Complete:<n>` and `Abandon:<n>` (the nth in hand); `GameDebug.Missions()` gives how many jobs the station offers, how many are in hand, how many have been finished, and the standing with the station's faction. A script's run is silent; `GameDebug.Sound(true, 0)` switches sound on at no loudness, so that its code runs, and `Sound()` gives how many sounds have been started (the menus' switch is `Menu:sound`). `GameDebug.Wreck()` is a cheat that leaves a pirate scout's wreck a kilometre off the pilot's ship, and `Salvage()` switches every salvager on, on the nearest wreck. `GameDebug.Give(type, n)` and `Train(skill, level)` are cheats for runs that test something other than buying and training; `Held()` gives the share of its speed a webifier leaves the pilot's ship and whether it is kept out of warp, and `Held('target')` the same for the first ship locked (`Fire()` switches on everything that takes a target, these included). `GameDebug.Traffic()` gives how many other ships the system has, how many are on the pilot's grid, and how many ships on the overview would fire on the pilot; `Standing(faction)` gives what a faction thinks of the pilot, `Marked()` says whether the patrols take the pilot for a criminal, and `Battery()` how many volleys of a station's batteries the scene has shown. `GameDebug.Security()` gives the security of the pilot's system and its band (`"secure"`, `"low"`, `"lawless"`), and `Pirates()` the number of pirates on the pilot's grid and how many of them the scene draws as a hull of the pirates' own with its weapons on. For fights, `GameDebug` also has `Lock(what)`, `Locked()`, `Fire()`, `Count(kind)`, `Hold(type)`, `Fitted(type)`, `Condition()`, `Wallet()`, `Hull()`, `Peaceful(on)` and `SelfDestruct()`.

## Looking at the game

| Command | What it does |
|---|---|
| `bin/launch APP --console` | A Luau prompt in the terminal that started the app: type a line, it runs in the app's VM. The harness command `lua CODE` does the same from a script. |
| `script/goldens [NAME ...]` | Runs the golden-screenshot scenarios and compares each with its stored image. |
| `script/goldens --update [NAME ...]` | Stores this run's screenshots as the golden images. |

`bin/launch APP --do "COMMANDS" --out DIR` drives an app with scripted input and saves screenshots; see `docs/harness.md`.
